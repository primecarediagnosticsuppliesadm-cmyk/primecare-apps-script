## Measurement commands

### PERF tenant certification (isolated scale)

```bash
cd primecare-portal

# Use existing seeded tenant (recommended)
PERF_SKIP_SEED=1 PERF_TENANT_ID=<tenant-uuid> node scripts/run-hq-performance-certification.mjs

# Full re-seed (requires service-role seed path — may FAIL on RLS)
node scripts/run-hq-performance-certification.mjs
```

Output: `docs/hq-certification/HQ_PERFORMANCE_CERTIFICATION.md`

### QA tenant navigation probe

```bash
node scripts/measure-hq-navigation-perf.mjs
```

### Ad-hoc Sprint 1 HQ read probe

```bash
node scripts/measure-sprint1-hq-reads.mjs --before   # label in output only
node scripts/measure-sprint1-hq-reads.mjs --after
```

Measures cold `force: true` API timings for dashboard, orders, collections, ops loader, EFI loader.

### Ad-hoc single surface timing

Use `perfTime` / `perfLog` in `primecareSupabaseApi.js` with browser network tab or script-level `performance.now()` wrapper.

## Largest slow query identification

From PERF cert report:

1. Sort benchmarks by `ms` descending
2. Record **slowest surface** in release scorecard
3. If slowest > 400 ms → investigate:
   - Missing index (`idx_orders_tenant_order_date`, `idx_payments_tenant_payment_date`)
   - Unbounded join (violation — fix immediately)
   - Parallel read fan-out (Operations Center)

**Current slowest (PERF):** Operations Center loader — **366 ms** (within gate)

## WARN handling

| WARN | Action |
|------|--------|
| Surface 400–500 ms | Document in scorecard; plan optimization |
| Surface > 500 ms | **FAIL** — block release |
| PERF seed RLS fail | Use existing PERF tenant; log GAP |
| Bundle > 500 kB | WARN only — not a cert blocker |
