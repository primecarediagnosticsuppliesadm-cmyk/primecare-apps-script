# Enterprise Architecture Enforcement Platform

**Purpose:** Automatically validate every change against Blueprint 00–18, Projection Registry, KPI Catalog, Certification Framework, and Enterprise Architecture Governance — preventing architectural drift from human or AI contributors.

**Scope:** Enforcement scripts, machine-readable catalogs, CI workflows, and health reports only. No business logic, finance, logistics, inventory, or RLS changes.

## Validator architecture

| # | Validator | Validates |
|---|-----------|-----------|
| 1 | **architecture-validator** | Blueprint tables, Field Dictionary, Registry projections, KPI single owner, API domains, screen adapters, projection bypass, duplicate KPI engines |
| 2 | **blueprint-validator** | Undocumented tables/RPCs/flags/routes/permissions/verify scripts/migrations → **Blueprint Drift Report** |
| 3 | **projection-validator** | Registry completeness, dependency acyclic graph, forbidden edges, workers, live parity/staleness (when creds present) |
| 4 | **api-validator** | Read/Write naming, bounded selects, adapter naming, deprecated bridge, RPC versioning, write→SoT only |
| 5 | **performance-validator** | N+1 patterns, unbounded selects, duplicate reads, bundle size, projection bypass |
| 6 | **security-validator** | RLS on new tables, SECURITY DEFINER tenant checks, permission SoT, hardcoded roles |
| 7 | **documentation-validator** | CHANGELOG, Blueprint, Registry, Cert matrix, ADR, TD register co-updated with changes |

---

## Execution order

```
1. documentation-validator  (fast — staged file requirements)
2. architecture-validator   (registry, KPI, domain rules)
3. blueprint-validator      (drift report)
4. api-validator            (API contracts)
5. security-validator       (RLS / tenant)
6. performance-validator    (static perf heuristics)
7. projection-validator     (graph + optional live cert)
```

Pre-commit runs subset: 1, 2, 3, 4 (incremental mode).

## npm scripts

```bash
cd primecare-portal

# Pre-commit equivalent (staged files only)
npm run enforce:pre-commit

# Pull request profile
npm run enforce:pr

# Full baseline (all legacy drift as WARN/INFO)
npm run enforce:full

# Single validator
npm run enforce:validator -- architecture-validator

# Enterprise health dashboard
npm run enforce:health
```

## Enforcement modes

| Mode | Env | Behavior |
|------|-----|----------|
| **incremental** | default | ERROR only on violations in **changed/staged** files; legacy baseline = WARN suppressed |
| **full** | `ENFORCEMENT_MODE=full` | All violations surface; used nightly / quarterly ARB |

## CI/CD integration

| Stage | Profile | Validators | Legacy scripts |
|-------|---------|------------|----------------|
| **Pre-commit** | `pre-commit` | arch, blueprint, api, doc | — |
| **Pull request** | `pr` | all 7 | `verify-bounded-reads.mjs`, `npm run build` |
| **QA deploy** | `qa-deploy` | all 7 (full) | parity, staleness, bounded reads, build |
| **Production** | `prod-deploy` | all except perf static | golden path, financial recon, monitoring |
| **Nightly** | `nightly` | all 7 (full) | parity, staleness, health dashboard |
| **Quarterly ARB** | `quarterly-arb` | all 7 + health dashboard | full cert bundle |

Install pre-commit hook (optional):

```bash
cp primecare-portal/scripts/enforcement/pre-commit.sh .git/hooks/pre-commit
chmod +x .git/hooks/pre-commit
```

## Rollback

1. Remove or disable git pre-commit hook.
2. Disable GitHub workflows (`architecture-enforcement.yml`).
3. Remove `enforce:*` npm scripts from package.json.
4. Delete `scripts/enforcement/` — **no impact on runtime application**.

Enforcement is entirely additive; rollback does not affect projections, finance, or RLS.

## GO / NO-GO

| Gate | Status |
|------|--------|
| Validator platform implemented | **GO** |
| Incremental mode for legacy codebase | **GO** |
| CI workflows defined | **GO** |
| Flip `ENFORCEMENT_MODE=full` on PR before baseline cleanup | **NO-GO** |
| Block commits on all blueprint drift day 1 | **NO-GO** — use incremental first |

**Recommended:** Enable pre-commit + PR workflow in **incremental** mode; run **full** nightly; tighten to full PR gate after drift report remediated.
